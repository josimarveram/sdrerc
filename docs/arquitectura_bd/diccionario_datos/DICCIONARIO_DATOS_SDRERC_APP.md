Este documento es el detalle columna por columna del modelo descrito conceptualmente en `docs/arquitectura_bd/diseño_datos/DISENO_DATOS_SDRERC_APP.md`. No se ejecutó SQL ni se consultó el diccionario de una base Oracle real: el contenido se extrajo leyendo los scripts `01` a `62` y refleja el modelo tal como quedaría si se ejecutaran en orden sobre un esquema vacío. El estado físico de cada ambiente debe verificarse contra `user_tab_columns`/`user_constraints` antes de una aprobación formal.

## 1. Alcance

Incluye, para cada tabla del esquema `SDRERC_APP`:

- columnas, tipo de dato, nulabilidad y valor por defecto;
- clave primaria y claves foráneas;
- claves únicas y checks relevantes;
- una descripción breve del propósito de negocio;
- el script donde se originó cada columna, cuando fue agregada después de la creación de la tabla.

No incluye: datos maestros/semilla (ver los propios scripts en `db/sdrerc_app/scripts`), plan de índices detallado más allá de lo declarado en script `08`, ni el modelo legacy (`APP_USERS` y esquema anterior), que permanece fuera de `SDRERC_APP`.

### 2.3 Notas de tipos

- `NUMBER(1)` se usa como booleano (`0`/`1`); no existe tipo `BOOLEAN` nativo en Oracle 11/12 compatible con el driver usado.
- Los identificadores primarios son `NUMBER GENERATED BY DEFAULT AS IDENTITY`, es decir, autoincrementales pero que aceptan un valor explícito si se provee (relevante para migraciones desde `ID_LEGACY`).
- `TIMESTAMP` se usa para fecha+hora de auditoría/eventos; `DATE` se usa para fechas de negocio sin hora relevante (vencimientos, fechas de acta, etc.).
- Los nombres de columnas y tablas en Oracle son case-insensitive; este documento los escribe en minúscula (como en los scripts) salvo en encabezados de tabla, donde se usa mayúscula por legibilidad.
